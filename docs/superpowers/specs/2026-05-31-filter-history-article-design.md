# Дизайн: фильтр по звёздам, /history, приём артикула, сводка

Дата: 2026-05-31
Статус: одобрено пользователем

## Контекст

Идеи позаимствованы из родственного проекта `lavren007/wb_parser_bot` после его изучения.
Заимствуем только UX-фичи; их хрупкий HTML-парсинг по CSS-селекторам НЕ переносим —
наш парсер перехватывает JSON из WB API и устойчивее к редизайну вёрстки.

Внедряем четыре фичи:
1. Фильтрация отзывов по звёздам (кнопки до сбора).
2. `/history` — последние 5 запусков с повторной отправкой файлов через Telegram `file_id`.
3. Приём чистого артикула (`12345678`) наравне со ссылкой.
4. Сводка после сбора (собрано X из Y, средний рейтинг).

## Решения (зафиксированы с пользователем)

- **Состояние между шагами**: FSM aiogram 3 (`StatesGroup` + `FSMContext`), а не dict в памяти.
  Проект уже использует FSM; второй механизм состояний не вводим.
- **Повторное скачивание**: через Telegram `file_id` (без диска — работает и на Railway, и на VPS).
- **Объём истории**: последние 5 успешных запусков.
- **Фильтр**: inline-кнопки после ссылки, с режимом ручного выбора галочками.
- **Rate-limit**: списывается на шаге выбора фильтра (callback), а не при получении ссылки.
- **Вопросы**: фильтр по звёздам к ним НЕ применяется (у вопросов нет рейтинга) — собираются всегда полностью.
- **Логика фильтрации**: чистая функция в `wb_parser_playwright.py`, покрыта юнит-тестами без браузера.

## Поток обработки (FSM)

```
Пользователь шлёт ссылку ИЛИ артикул "12345678"
        │
        ▼
handle_url:  валидация (URL или чистый артикул) → проверка подписки
        │    (rate-limit здесь НЕ трогаем)
        ▼
   FSMContext: {url, product_id, marketplace}; state = WaitingFilter
   показываем inline-кнопки фильтра
        │
        ▼
callback "flt:*":  читаем state → проверяем rate-limit → списываем запрос
        │
        ▼
   run_collection: парсинг → фильтрация отзывов → Excel → отправка
        │          → сохраняем file_id в БД → сводка → state.clear()
        ▼
   готово
```

Граничные случаи:
- `/cancel` дополнительно делает `state.clear()`.
- Сессия устарела (бот перезапущен, state пуст): callback отвечает «⚠️ Сессия устарела, отправьте ссылку заново».
- Группы по-прежнему игнорируются (`F.chat.type == "private"` сохраняется).

## Фильтрация по звёздам

Клавиатуры (в `bot.py`):
- Пресеты: `⭐ Все` `1★` `1–2★` `1–3★` `4–5★` `🔢 Выбрать вручную`
- Ручной режим: тогглы `1★…5★` (✅ у выбранных), `✅ Готово`, `🔙 Назад`

callback_data (умещаются в 64 байта):
- `flt:all`, `flt:1`, `flt:1-2`, `flt:1-3`, `flt:4-5`, `flt:custom`
- `star:1…star:5` (тоггл), `flt:done`, `flt:back`
- Выбранные галочки — в FSMContext (`custom_stars`).

Функция фильтрации (`wb_parser_playwright.py`):
```python
def filter_reviews_by_rating(reviews: list[dict], filter_type: str) -> list[dict]:
    """filter_type: 'all' | '1'..'5' | '1-2' | '1-3' | '4-5' | '2,5' (кастом)."""
```
- `all` → без изменений
- диапазоны/одиночные/кастом → по `review['rating']` (int 1–5)
- вопросы не фильтруются

Тесты: `tests/test_filter.py` — all, каждый пресет, кастом-набор, пустой список,
рейтинг=0, некорректный filter_type.

## /history через file_id

Схема БД — расширяем `requests` (правим И `database.py`, И `supabase_database.py`):
```sql
ALTER TABLE requests ADD COLUMN filter_type TEXT;
ALTER TABLE requests ADD COLUMN questions_count INTEGER DEFAULT 0;
ALTER TABLE requests ADD COLUMN avg_rating REAL DEFAULT 0;
ALTER TABLE requests ADD COLUMN reviews_file_id TEXT;
ALTER TABLE requests ADD COLUMN questions_file_id TEXT;
```
SQLite: миграция через `ALTER TABLE` с проверкой `PRAGMA table_info`, чтобы не падать на старой БД.
`add_request` расширяется новыми полями. `get_recent_requests(user_id, limit=5)` расширяется,
чтобы возвращать file_id и фильтр.

file_id: `answer_document` возвращает Message с `.document.file_id` — сохраняем строку.
`/history` показывает последние 5 успешных запусков + inline-кнопки `📥 Скачать #N` → `dl:<request_id>`.
В выборку попадают только записи с `success=1` и непустым `reviews_file_id` (у неуспешных запусков file_id нет).
Если история пуста — сообщение «📭 История пока пуста».
По нажатию — `answer_document(file_id)` без диска и пересбора.
Если file_id протух — ловим ошибку, предлагаем отправить ссылку заново.

## Приём чистого артикула

В `url_validator.py`: если ввод `.isdigit()` и длина 6–12 цифр →
строим канонический URL `https://www.wildberries.ru/catalog/{article}/detail.aspx`,
дальше обычный путь валидации. Тесты в `test_url_validator.py`.

## Сводка после сбора

Финальное сообщение при успехе:
```
✅ Готово!
📦 Артикул: 12345678
🔍 Фильтр: 1–3★
⭐ Отзывов: 33 (всего 148 без фильтра)
❓ Вопросов: 32
📊 Средний рейтинг: 2.1
```
`avg_rating` считается по отфильтрованным отзывам.
